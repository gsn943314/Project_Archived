# 2026-11-12 mcptest — 用 unreal-mcp 做 NavMesh 尋路解謎原型

---

## 完成的功能

### 1. unreal-mcp 連線與唯讀查詢

用 `/mcp` 重新連上 `unreal-mcp` 後，先用 `GetSelectedActors`、`GetLabel` 唯讀查詢目前選取的 Actor，結果是 `SM_Cylinder`（`StaticMeshActor_59`，位於 `/Game/FirstPerson/Lvl_FirstPerson`）。這一步確認了 MCP 可以讀取 Editor 狀態，而且不會修改場景。

### 2. 美術／程式分流的資料夾結構

新增 `/Game/Project`，模板原有的資料夾沒有移動：

```text
/Game/Project/
├── Art/          Meshes, Materials, Textures, Animations, VFX, UI
└── Programming/  Blueprints, Input, Data, AI, UI
```

UI 拆成兩部分：圖像素材放 `Art/UI`，Widget Blueprint 放 `Programming/UI`。

### 3. A → B 最短可行走路徑尋路

- 用 `NavMeshBoundsVolume_Pathfinding` 涵蓋地板，產生 NavMesh。
- `BP_PathfindingCharacter` 是 AI 控制的角色，使用 Quinn 模型。它用 `AI MoveTo` 走向 `TargetPoint`，也就是 B 點。
- 路徑由 NavMesh（A*）計算，是可行走範圍內的最短路徑，不是直線距離。
- 第一版測試：直線距離 1521 cm，實際可行走路徑 2572 cm，角色會繞過障礙物，約 6 秒抵達 B 點。

### 4. 俯視鏡頭與遊戲循環

主要由 `BP_PathfindingPlayerController` 控制，用 `Phase` 變數管理狀態：

| Phase | 狀態 | 行為 |
|-------|------|------|
| 0 | PLANNING | 俯視鏡頭（`OverviewCamera`），每個 Tick 用 `FindPathToLocationSynchronously` 畫出路徑預覽：綠線表示可抵達，紅線加 BLOCKED 標示表示被擋住 |
| 1 | RUNNING | `SetViewTargetWithBlend` 把鏡頭切到角色並跟隨 |
| 2 | ARRIVED / BLOCKED | 抵達時等待玩家按 RESET；被擋住時等 2.5 秒後自動執行 `ResetRun` |

- 可以編輯的障礙物是 `BP_EditableObstacle`，帶有 `Editable` tag，使用紫色材質 `MI_EditableObstacle`。
- 操作方式：`W`／`E`／`R` 切換移動、旋轉、縮放，滑鼠拖曳或滾輪調整。縮放下限是 0.15。
- 介面是 `WBP_PathfindingHUD`，包含 PLAY、RESET 兩個按鈕，以及 Phase、Path、Selection、Mode 四個文字欄位。
- 新增 `BP_PathfindingGameMode`，只用在這個關卡的 GameMode override，不影響其他關卡。
- NavMesh 的 Runtime Generation 改成 **Dynamic**，障礙物移動後路徑會在 2 秒內重新計算（測試結果：2687 → 2650 cm）。

### 5. 單一路徑解謎關卡 `Lvl_PathfindingPuzzle`

新建關卡 `/Game/Project/Maps/Lvl_PathfindingPuzzle`，從 `Template_Default` 建立，沒有使用 World Partition。

- 迷宮由 Python 腳本產生：13 × 10 格，每格 350 cm，共 18 格走廊、18 段合併牆、6 個轉角，中段有一段先上後下的坡道。
- A 點在 `(-1750, -1225)`，B 點在 `(1750, 1225)`，紫色閘門在 `(700, 525)`，把走廊完全擋住。
- 走廊設計成階梯狀，一路逐漸靠近 B 點。原因是 B 點無法抵達時，NavMesh 會回傳 **partial path**，終點是「可抵達範圍內最接近 B 的點」；階梯形狀能確保這個點剛好在閘門前。如果做成會折返的 S 形路線，角色會停在錯的位置。
- 角色的 `StartRun` 改成先計算路徑，取 partial path 的最後一個點作為 `RunDestination`，再用 `AI MoveTo` 走過去。`NotifyRunFinished` 用「與 B 點的 2D 距離 ≤ AcceptanceRadius + 80」判斷是否真的抵達。
- 美術：新增 `MI_MazeWall`（暗色）、`MI_MazeFloor`（淺色走廊）、`MI_MazeBackdrop`，以及無邊界的 `PostProcess_FixedExposure`（自動曝光 min/max 都固定為 1.0，bias −0.5）。

**踩坑過程**：

- 原本把牆設成深色材質，畫面上卻還是淺灰色。第一個懷疑是材質沒套上，但查過後材質是正確的，問題出在自動曝光把畫面拉亮了。
- 加了 PostProcessVolume 鎖定曝光後，bias 設 −1.5 又太暗，最後改成 −0.5，並另外給走廊地板一個較亮的專用材質。

### 6. Crash 原因追查與隱藏風險掃描

Editor 在自動化測試時 crash。從 `~/Library/Logs/Unreal Engine/mcptestEditor/mcptest-backup-2026.11.12-21.55.57.log` 找到的錯誤是：

```text
Assertion failed: GameViewport.IsUnique()  [SLevelViewport.cpp:5242]
SLevelViewport::EndPlayInEditorSession ← UEditorEngine::EndPlayMap
```

原因是測試腳本在同一個 Python 呼叫裡先 `StopPIE`，緊接著又 `StartPIE`，上一個 PIE 的 viewport 還沒清理完就被引用，觸發 assertion。這是測試方式造成的，和遊戲邏輯無關。crash 前最後一次存檔（16:55）有寫入磁碟，沒有遺失任何成果。

之後也掃描了 log 和 Blueprint 原始碼：

| 檢查項目 | 結果 |
|----------|------|
| Blueprint Runtime Error／Accessed None | 0 筆 |
| `ResetRun` 的順序 | 先 `EnterPlanning`（Phase = 0）再 `ResetToStart`。`StopMovement` 中斷移動時觸發的 OnFail 會被 `Phase == 1` 的檢查擋掉，不會誤判成 BLOCKED |
| BLOCKED 等待 2.5 秒期間按 RESET 或 PLAY | Delay 結束後會再檢查 `Phase == 2`，不會重複重置 |
| 縮放下限 | 0.15，不會縮到 0 或變成負值 |
| NavigationSystem CDO ensure（21:35） | 舊關卡測試時 Python 呼叫方式造成的 handled ensure，不會 crash |
| NavMesh「3 tile limit reached」（21:18） | 發生在舊的 FirstPerson 關卡，新關卡沒有出現 |
| 啟動 PIE 3 秒內 Phase 自己變成 RUNNING | 同一份 Blueprint 在 2 秒時測到的 Phase 是 0；之後只改了材質和曝光，沒有動邏輯。判斷是外部操作造成的，不是自動開跑的 bug |

## 遇到的問題

| 問題 | 解法 |
|------|------|
| 修改 Blueprint 後，FirstPerson 關卡（World Partition）裡的角色在 reinstancing 時損壞，掉出世界 | 在同一位置、同樣朝向和 Target 設定下放了新的角色；存檔時 World Partition 自動刪掉舊的 external actor package。新關卡改用非 World Partition 的模板，避免再發生 |
| 障礙物移動後路徑不會更新 | NavMesh Runtime Generation 改成 Dynamic |
| B 點被擋住時角色停錯位置 | 走廊改成逐步靠近 B 點的階梯形狀，並且走到 partial path 的終點 |
| 深色材質在畫面上變成淺灰色 | 用 PostProcessVolume 鎖定曝光，bias −0.5 |
| DSL 寫入時出現 `Unclosed parenthesis` | 補上缺少的右括號後重新寫入，編譯通過 |
| 連續 `StopPIE` → `StartPIE` 讓 Editor crash | 停止和啟動 PIE 分成兩次呼叫，中間等 PIE 完全結束 |
| 重開 Editor 後 MCP 監聽 port 8000 綁定失敗（`HttpListener unable to bind to 127.0.0.1:8000`），`unreal-mcp` 出現 ECONNREFUSED | crash 後殘留的 process 可能還佔著 port。等它釋放後再重開 Editor，或到 Editor Preferences → Model Context Protocol 改 port |
