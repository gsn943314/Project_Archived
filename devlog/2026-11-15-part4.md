# 2026-11-15 mcptest — Glitch 觸發點、被抓修正、Creator HUD、對話框改版

---

## 完成的功能

### 1. 被野獸抓到時一定觸發倒地＋Glitch（Level 1）

- `OnCaught` 的 `bCaught` 是「每一輪只觸發一次」的旗標，原本從來沒有被重設，第二輪起被抓完全沒反應，小狐卡在 RUNNING。現在 `StartRun` 會把它重設。
- 追擊者的撞到距離從膠囊半徑 + 60 cm 改成 + 125 cm（約 170 cm）。野獸模型很大，並排或斜著頂住小狐時，中心距離常停在判定範圍外。
- `OnRunFinished` 的 BLOCKED 分支先檢查 2 m 內有沒有 `BP_EnemyChaser`：有就當成被抓。2 m 是為了不把隔著柵欄的野獸（約 4.4 m 外）誤判成撞到。

### 2. Glitch 觸發點 `BP_GlitchSpot`

- 小狐在 Phase 1 走進觸發範圍時，`Target` 美術會撕裂 `GlitchDur` 秒（實作在 `BP_PortalGlitch.SetupActor`）。`ScreenAmt` > 0 時，同時播一次全螢幕 Glitch。
- 觸發點掛 `Say:` tag 時，第一次經過會讓小狐停下、轉向 Target、播放台詞（期間追擊者暫停）。只有整段台詞播完才算講過，中途被抓、RESET 或 BLOCKED 都不算。
- Level 1 放了兩個：
  - `GlitchSpot_Camp`：位置 (1400, -875)，半徑 3 m，Target 是帳篷，有兩句台詞。
  - `GlitchSpot_Arch`：Target 是 `Art_ExitArch`，半徑 9 m，撕裂 4 s，加全螢幕強度 0.45。

**踩坑過程**：
- 第一次重現時，PIE 世界裡完全找不到觸發點。原因是編輯器開著的那份關卡沒有它們，可能是被 Undo 掉了。
- 拱門一開始抓錯成 `Art_RightLandingWall`，使用者指正後改成 `Art_ExitArch`。觸發點原本放在平台高度，小狐要爬上樓梯才會觸發，太晚；之後移到 z 150、加大半徑。
- 帳篷原本以帳篷中心為圓心、半徑 6.5 m。樓梯口剛好在邊緣，小狐提早轉上樓梯時就會擦過去，造成偶發不觸發。使用者的 Output Log 有 `BeginPlay` 卻沒有 `talk START`，才確認是這個原因，最後把觸發點移到樓梯口轉角。
- 加了 Output Log 追查紀錄：`GlitchSpot BeginPlay` / `talk START` / `talk END talked=`。

### 3. Creator Access HUD（設計稿 A）

- 貼圖匯入到 `/Game/Project/Art/UI/CreatorHUD/`。
- `WBP_PathfindingHUD` 新增 `CreatorCard`，內容有：
  - 底板、標題「CREATOR ACCESS」
  - 目標文字 `GoalText`
  - 共用遮罩染色的 Play / Reset 按鈕：可按是 #EDFC35，停用是 #7D8599
- 沿用原本的 `PlayButton` / `ResetButton`，控制器的程式不用改。
- 舊的資訊面板 `Panel` 設成 Collapsed，保留給除錯用。

### 4. 對話框：逐字打出、點擊跳句、Storybook 外觀、說話者名牌

- `BP_DialogueDriver` 由 `BP_PathfindingGameMode` 生成，每幀處理畫面上所有 `WBP_Dialogue`：
  - 每秒打出 45 字。
  - 在對話框上點擊：還在打字就立刻顯示整句；已經打完就設 `bAdvance`，呼叫端看到後切下一句。
  - 三個呼叫端已接上 `bAdvance`：`BP_GlitchSpot`、`BP_FoxLook`、控制器的 `UpdateHint`。
- 外觀換成 Storybook Dialogue A：
  - 米色底板。
  - 綠色名牌固定 334×120，維持原圖比例；名字太長時，`ScaleBox` 只縮小、不放大。
  - 棕色 V 形繼續箭頭，句子打完才閃爍顯示。
  - C 版貼圖也已匯入，還沒使用。
- 名牌規則：
  - `bSystem`（`BP_FoxLook` 的 `SYS:` 台詞）顯示 `SYSTEM`。
  - 其他都是小狐，依外觀階段 `BP_FoxLook.Stage` 顯示 `BP_GreyFox` / `SK_Fox_WIP` / `Fox`。
- 文字顏色由 Driver 統一設定：小狐深棕、系統深綠。

**踩坑過程**：
- 名牌第一版用自動寬度加九宮格拉伸，圖被拉長變形；改回固定原比例。
- 使用者覺得原本的灰模名 `BP_PathfindingCharacter` 太長，改成較短的假檔名。

### 5. Level 0 進灰盒時的小狐獨白（`BP_IntroTalk`）

- 開場動畫結束、第一次進灰盒時，先等 1.6 s 讓轉場 Glitch 過去，再依序播 `IntroTalk_Greybox` 的 4 句 `Say:` 台詞，例如「Where am I?」「Why is everything grey?」。
- 整關只播一次，按 PLAY 就結束。

### 6. 石頭野獸材質跑掉

- `M_RockEnemy` 用在骨架網格上，卻沒勾 **Used with Skeletal Mesh**。Editor 只會在記憶體裡自動補勾、不會存檔，所以自己電腦時好時壞，隊友拉下來就變成預設灰格材質。
- 已勾選並存檔。也檢查了專案裡其他骨架網格用的材質，只有這一個缺。

## 遇到的問題

| 問題 | 解法 |
|------|------|
| 第二輪起被抓沒反應、卡在 RUNNING | `StartRun` 重設 `bCaught`；撞到距離加大到膠囊半徑 + 125 cm |
| 帳篷對話偶爾不觸發 | 觸發點從帳篷中心移到樓梯口轉角，半徑 3 m |
| Editor 閃退（`PlayLevel.cpp:558`，PIE 物件被 TransBuffer 參照） | PIE 中用 `execute_python` 改遊戲物件會記進 Undo，StopPIE 時中止。PIE 中只做唯讀查詢，要觸發事件改用 `ke <actor> <事件>` |
| 閃退後對話加速完全沒效 | `BP_DialogueDriver` 存到的是還沒寫邏輯的空殼。DSL Write 只編譯不存檔，之後每改一個藍圖就立刻 `save_asset` |
| 敵人材質在隊友電腦跑掉 | `M_RockEnemy` 勾 Used with Skeletal Mesh 並存檔 |
| 名牌名字沒置中、超框、拉伸變形 | 名牌固定原比例，`ScaleBox` 縮字，對齊對話文字 |
